Create Admin and Staff roles with mock login.

Admin sees everything. Staff sees Dashboard, Patients, Invoices, Payments and Reports only.

The clinic workspace uses local mock data for patients and invoices. Payment records are saved in MongoDB Atlas.

## MongoDB and payments

Set the following variables in `.env.local` for local development. Keep this file out of source control:

```env
MONGODB_URI=mongodb+srv://<username>:<password>@<cluster-host>/
MONGODB_DB_NAME=marine_clinic_care
```

The Payments section lists the most recent 500 records from the `payments` collection and lets staff record a payment with a patient, optional invoice, payment method, amount, and optional transaction reference. Payment amounts are stored as numeric INR values. Configure Atlas network access to allow the app's server environment to connect.

This project uses email/password authentication with MongoDB-stored password hashes and signed HTTP-only sessions. Unauthenticated server-function requests are rejected.

## Clinic email/password authentication

Set `SESSION_SECRET` to a long random value in `.env.local`. For an initial account, configure and restart the app with:

```env
CLINIC_ADMIN_EMAIL=admin@clinic.com
CLINIC_ADMIN_PASSWORD=<choose-a-strong-password>
CLINIC_STAFF_EMAIL=
CLINIC_STAFF_PASSWORD=
```

The bootstrap account is created once on the next sign-in attempt. Remove the bootstrap password variables after creating the account, or keep them only as a controlled recovery mechanism. Additional users can be stored in the MongoDB `clinic_users` collection with a `passwordHash` generated by the clinic provisioning workflow:

```json
{"email":"staff@clinic.example","name":"Clinic User","role":"staff","active":true,"passwordHash":"scrypt:<salt>:<hash>"}
```

Use `role: "admin"` only for clinic administrators. Never store plaintext passwords.
